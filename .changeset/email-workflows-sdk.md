Add experimental durable email workflows at `@opencoredev/email-sdk/workflows`. Define drips and onboarding sequences as step functions with `ctx.send`, `ctx.sleep`, `ctx.waitForEvent` (with timeouts), and `ctx.step`; branch with plain TypeScript; cancel runs by id, by `cancelOn` events such as `unsubscribed`, or through an `isSuppressed` check. Each send carries a stable idempotency key, `wf_` plus the hex SHA-256 of the JSON-encoded `[runId, step]` pair (67 characters, from `workflowIdempotencyKey`), completed steps are journaled so replays never repeat them, failed steps retry on timers, and workers claim runs with revision-checked leases so several processes can share one store. Storage and timers plug in through small `WorkflowStore` and `WorkflowScheduler` interfaces (lease-expiry timers carry an `owner` to pass back as `engine.resume(runId, { owner })`), with in-memory versions and a manual clock for tests. While a `ctx.step` callback is in flight, any other `ctx` call on that run, from inside the callback or beside the pending step, fails the run at once with `invalid_definition`, so a nested call can never wait on its own step. `WorkflowEmailSender.send` gets the run id and step name as an optional third argument (`WorkflowSendContext`), which an `EmailClient` ignores. The package root does not import the new entry, so the main bundle is unchanged.
