Add an experimental `native` send option for provider-specific features. Its keys are adapter names, TypeScript infers the accepted keys and shapes from the client's adapters, and each adapter in a fallback chain receives only its own entry. Resend, Postmark, SendGrid, SES, Mailgun, Brevo, and Loops get typed options for templates, tracking, streams, configuration sets, sandbox and test modes, and more. Resend and Brevo template sends still send the message `subject` as an override; set `useTemplateSubject: true` to keep the template's subject. Most HTTP JSON adapters accept a typed `body`/`headers` passthrough (Mailgun: `fields`) for fields the SDK doesn't model. `sendPersonalized` rejects that passthrough because it can replace the recipients the result reports, and a native request header can't name one the adapter or transport sets itself, such as credentials, `Content-Type`, or SES's SigV4 signing headers. Resend reserves `Idempotency-Key` on every send, so per-send keys always come from the `idempotencyKey` option and each `sendPersonalized` recipient keeps its own key. Telemetry doesn't infer submitted recipients for a send whose `body` or `fields` passthrough may have replaced them. Existing `EmailSendOptions` annotations keep compiling, and sends without `native` are unchanged.
