---
title: Test email sending without sending real email
description: "Test email sending in Node.js and TypeScript without sending real email: capture messages in memory, prove retries and fallback, or route SMTP to Mailpit."
---

To test email sending in a Node.js or TypeScript app without sending real email, swap the provider adapter for `memoryAdapter()` from `@opencoredev/email-sdk/testing`. It makes no network calls and keeps every message your code sends, so a test can check the recipients, subject, and body. Use `failingAdapter()` to test retries and fallback, and point the [SMTP adapter](/docs/adapters/smtp) at a local catcher such as Mailpit when you need to see the rendered MIME message.

| What you want to prove | Use | Network |
| --- | --- | --- |
| Your code sends the right message | `memoryAdapter()` | None |
| Retries and fallback behave | `failingAdapter()` + `memoryAdapter()` | None |
| Hooks and plugins run in order | `capturePlugin()` | None |
| The real MIME message renders | `smtp()` pointed at Mailpit | Local only |

Delivery to real inboxes still needs a real send from your own provider account.

## Capture a successful send

```ts title="src/email.test.ts"
import { expect, test } from "bun:test";
import { createEmailClient } from "@opencoredev/email-sdk";
import { memoryAdapter } from "@opencoredev/email-sdk/testing";

const memory = memoryAdapter();
const email = createEmailClient({ adapters: [memory] });

await email.send({
  from: "Acme <hello@acme.com>",
  to: "user@example.com",
  subject: "Welcome",
  text: "Your account is ready.",
});

expect(memory.raw?.sent).toHaveLength(1);
expect(memory.raw?.sent[0]?.message.subject).toBe("Welcome");
```

`memory.raw.clear()` resets the store.

## Prove fallback behavior

Fallback advances automatically only after a `not_sent` failure.

```ts title="src/email.test.ts"
import { EmailAdapterError } from "@opencoredev/email-sdk";
import { failingAdapter, memoryAdapter } from "@opencoredev/email-sdk/testing";

const primary = failingAdapter(
  "primary",
  new EmailAdapterError("Rejected before acceptance", {
    adapter: "primary",
    retryable: false,
    delivery: "not_sent",
  }),
);
const backup = memoryAdapter("backup");

const email = createEmailClient({
  adapters: [primary, backup],
  fallback: { adapters: ["backup"] },
});

const result = await email.send(message);
expect(result.adapter).toBe("backup");
```

Use `delivery: "unknown"` to prove the default route stops instead of risking a duplicate.

## Prove retry counts

`maxAttempts` is the total call count. Set `delay: () => 0` in tests.

```ts title="src/email.test.ts"
const email = createEmailClient({
  adapters: [primary],
  retry: {
    maxAttempts: 3,
    delay: () => 0,
  },
});
```

## Capture lifecycle events

Use `capturePlugin()` when a test needs ordered `beforeSend`, `retry`, `afterSend`, and `error` records.

## Inspect the real message with a local SMTP catcher

The memory adapter stores the message object, not the MIME a provider would receive. To look at headers, encodings, and attachments as a mail client sees them, run a local catcher such as [Mailpit](https://mailpit.axllent.org/) and send through the SMTP adapter. Mailpit accepts mail on port 1025 and shows it in a web UI on port 8025; nothing leaves your machine.

```ts title="src/email.dev.ts"
import { createEmailClient } from "@opencoredev/email-sdk";
import { smtp } from "@opencoredev/email-sdk/smtp";

export const email = createEmailClient({
  adapters: [smtp({ host: "127.0.0.1", port: 1025 })],
});
```

With no `auth`, the adapter doesn't require TLS, so it can talk to a local catcher that has none. This repository runs the same setup in its own SMTP check.

## Keep telemetry off

The repository test preload sets `EMAIL_SDK_TELEMETRY=0`. Application tests can also construct clients with `telemetry: false`.

## Questions

### Does `memoryAdapter()` send anything?

No. Its `send` pushes the message and a result with an id like `mem_1` into `memory.raw.sent` and returns. Nothing goes over the network.

### Does it work with Vitest or Jest?

Yes. The adapter is plain TypeScript with no test-runner dependency. The examples use `bun:test`; swap the `expect` import for your runner's.

### How do I test that fallback does not cause duplicates?

Make the primary adapter fail with `delivery: "unknown"`. With the default `onUnknownDelivery: "stop"`, the send throws instead of trying the backup, and `memory.raw.sent` stays empty. See [retries and fallback](/docs/concepts/fallbacks-and-retries).

### Can I keep the same client code in tests and production?

Yes. Build the client from a list of adapters and pass `memoryAdapter()` in tests and your provider adapter in production. The `send` calls don't change.
