---
title: Install
description: Install the ESM-only SDK for Node.js 20+ or Bun 1.1+.
---

<Steps>

<Step>

### Install the package

<PackageInstallTabs />

```bash
npm install @opencoredev/email-sdk
# Or:
bun add @opencoredev/email-sdk
```

For a complete runnable project, copy the [first-send starter](https://github.com/opencoredev/email-sdk/tree/main/packages/email-sdk/examples/first-send) and run `npm install` inside it. It declares `@opencoredev/email-sdk` and `dotenv`; the SDK does not read `.env` files on its own. The [quickstart](/docs/getting-started/quickstart) walks through it.

The public package is `@opencoredev/email-sdk`. The unscoped `email-sdk` package on npm is unrelated.

</Step>

<Step>

### Confirm your runtime

Use Node.js 20+ or Bun 1.1+. The package is ESM-only, so use `import` syntax or dynamic `import()` from a CommonJS application.

```json title="package.json"
{
  "type": "module"
}
```

</Step>

<Step>

### Import one adapter

Adapters use separate package entry points, so your application imports only the integrations it uses.

```ts title="email.ts"
import { createEmailClient } from "@opencoredev/email-sdk";
import { resend } from "@opencoredev/email-sdk/resend";
```

</Step>

<Step>

### Verify the CLI

Run the CLI through the scoped package so the unrelated unscoped `email-sdk` package is never resolved. The built CLI uses a Node shebang and also runs under Bun.

```bash
npm exec --package=@opencoredev/email-sdk -- email-sdk version
npm exec --package=@opencoredev/email-sdk -- email-sdk adapters
# Bun:
bunx --package @opencoredev/email-sdk email-sdk version
```

Inside a project that already installed the package, `./node_modules/.bin/email-sdk version` runs the same binary.

For a global Homebrew install, use `brew install opencoredev/tap/email-sdk` after the formula points at a published release.

</Step>

</Steps>
