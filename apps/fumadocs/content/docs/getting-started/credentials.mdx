---
title: Provider credentials
description: Configure adapter credentials in the server environment and verify required values with the CLI.
---

Credentials belong in the server process that constructs the adapter. Email SDK does not read a universal configuration file or expose credentials to browser code.

## Required environment variables

Run the adapter catalog to see the names required by the bundled CLI.

```bash
npm exec --package=@opencoredev/email-sdk -- email-sdk adapters
```

Common adapters use these values:

| Adapter | Required environment variables |
| --- | --- |
| Resend | `RESEND_API_KEY` |
| Postmark | `POSTMARK_SERVER_TOKEN` |
| SendGrid | `SENDGRID_API_KEY` |
| AWS SES | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` |
| Mailgun | `MAILGUN_API_KEY`, `MAILGUN_DOMAIN` |
| Cloudflare | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` |
| SMTP | `SMTP_HOST`; auth also uses `SMTP_USER` and `SMTP_PASS` |

The [adapter pages](/docs/adapters) list every credential and adapter-specific option.

## Pass credentials to application code

Adapter factories accept credentials explicitly. Environment variable names are a deployment convention rather than a hidden SDK lookup.

```ts title="src/email.ts"
import { resend } from "@opencoredev/email-sdk/resend";

export const resendAdapter = resend({
  apiKey: process.env.RESEND_API_KEY!,
});
```

## Check configuration

Default `doctor` checks configuration only; it does not authenticate. Export credentials into your server shell first (the CLI does not read `.env`). Credential flags override environment values, but environment variables avoid putting secrets in command history.

```bash
# Configuration only, no network:
npm exec --package=@opencoredev/email-sdk -- email-sdk doctor --adapter resend
# Authenticate the key and check the Resend sender domain, no email sent:
npm exec --package=@opencoredev/email-sdk -- email-sdk doctor --adapter resend --live --from "$EMAIL_FROM" --json
```

`./node_modules/.bin/email-sdk` is the same binary once the package is installed in a project. Live authentication supports Resend, Sequenzy, JetEmail, Primitive, Lettermint, and Lettr; sender readiness is Resend-only. A send-only key may lack the read permission the sender check needs, so an insufficient-permissions result is not proof the key cannot send. Neither authentication nor domain readiness proves inbox delivery.

Use `send --dry-run` to validate a full message without provider delivery, even without real credentials. SDK/CLI telemetry is on by default; `EMAIL_SDK_TELEMETRY=0` or `DO_NOT_TRACK=1` disables it.

## Environment files

The SDK and CLI never read `.env` or `.env.local`. Export variables in the process or use your framework's server loader. The [first-send starter](https://github.com/opencoredev/email-sdk/tree/main/packages/email-sdk/examples/first-send) uses `dotenv` explicitly: process environment wins, then `.env.local`, then `.env`, relative to its script. Bun preloads `.env` on its own before any script runs; `bun --no-env-file first-send.mjs` leaves loading entirely to the starter.

Keep keys server-only, out of public-prefixed variables, browser bundles, logs, and version control. Git-ignore local environment files and commit only a placeholder template such as the starter's `.env.example`.

## Resend: domain verification and test limits

The starter uses `RESEND_API_KEY`, `EMAIL_FROM`, and `EMAIL_TO`.

- Resend sends from domains you own; [add and verify a domain](https://resend.com/docs/dashboard/domains/introduction) before using your own address in `EMAIL_FROM`.
- The shared `onboarding@resend.dev` sender is for testing and can only send to the email address on your Resend account. Any other recipient gets HTTP 403 `You can only send testing emails to your own email address (...)` ([Resend knowledge base](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)).
- Free plans have daily and monthly quotas that return HTTP 429 ([Resend error reference](https://resend.com/docs/api-reference/errors)).
- `delivered@resend.dev`, `bounced@resend.dev`, and `complained@resend.dev` are [Resend test recipients](https://resend.com/docs/dashboard/emails/send-test-emails) that simulate outcomes without a real inbox.

A successful send returns a provider `id`. That is a receipt for acceptance, not delivery; track delivered, bounced, and complained outcomes through [webhooks](/docs/reference/webhooks) or the provider dashboard.

## SMTP transport security

SMTP auth on a non-secure port requires TLS. The transport upgrades with STARTTLS by default. Set `allowInsecureAuth` only for a trusted local test server.
